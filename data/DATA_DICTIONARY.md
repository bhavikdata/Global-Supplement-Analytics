# Data Dictionary — Global Supplement Sales & Inventory Analytics

All data in this project is **100% synthetic**, generated by `scripts/generate_data.py`
with a fixed random seed (`SEED = 42`) for full reproducibility. No real company,
product, customer, or transaction is represented anywhere in this dataset.

Two layers of tables exist, matching the workbook's data model:

- **Fact/dimension tables** (`data/clean/*.csv`, normalized): the exact schema
  requested for this project — keys and core measures only.
- **Reporting tables** (`Sales_Reporting.csv`, `Inventory_Reporting.csv`):
  denormalized extracts produced by joining the fact tables to their dimensions,
  equivalent to a Power Query "Merge Queries" step. All dashboard/analysis
  formulas in the Excel workbook read from these reporting tables — see
  "Why a separate reporting layer?" below.

|---|---|---|

| OrderID | Integer | Order identifier (multiple lines can share one order) |
| OrderDate | Date | Date the order line was placed |
| ProductID | Integer (FK → Products) | |
| CountryID | Integer (FK → Geography) | |

| SellingPrice | Decimal ($) | Actual unit price after discount |

## 6. Sales_Reporting — denormalized reporting layer (`Sales_Reporting.csv`) — 54,573 rows

Same grain as Sales, joined to Products/Geography/Channels plus derived date keys:
OrderLineID, OrderID, OrderDate, **Year, YearMonth** (derived from OrderDate),
ProductID, **ProductName, Category** (joined from Products), CountryID,
**Country, Region** (joined from Geography), ChannelID, **ChannelName** (joined
from Channels), Units, SellingPrice, Discount, Revenue, Cost, GrossProfit.

## 7. Inventory — fact table, monthly snapshot grain (`Inventory.csv`, clean) — 2,880 rows

Grain: **one row per Product × Country × SnapshotMonth** (15 products × 8 countries × 24 months).

| Column | Type | Description |
|---|---|---|
| SnapshotMonth | Text ("YYYY-MM") | Month of the snapshot |
| ProductID | Integer (FK → Products) | |
| CountryID | Integer (FK → Geography) | |
| OpeningStock | Integer | Stock at the start of the month |
| Receipts | Integer | Units received from suppliers during the month (0 if delayed) |
| UnitsSold | Integer | Units sold during the month |
| ClosingStock | Integer | OpeningStock + Receipts − UnitsSold (balance holds for every row) |
| StockoutFlag | 0/1 | 1 if ClosingStock hit 0, or fell below 15% of ReorderPoint |

## 8. Inventory_Reporting — denormalized reporting layer (`Inventory_Reporting.csv`) — 2,880 rows

Same grain as Inventory, joined to Products/Geography plus derived fields:
SnapshotMonth, ProductID, **ProductName, Category**, CountryID, **Country,
Region**, OpeningStock, Receipts, UnitsSold, ClosingStock, StockoutFlag,
**ReorderPoint, TargetStock** (joined from Products), **DaysOfCover** =
ClosingStock / (UnitsSold/30), **ReorderAlert** = 1 if ClosingStock <
ReorderPoint, **SlowMoving** = 1 if UnitsSold < 3% of TargetStock.

## Why a separate reporting layer?

The Sales and Inventory fact tables above match the exact normalized schema
requested for this project. For dashboard and analysis formulas, though,
every SUMIFS/COUNTIFS/AVERAGEIFS call needs to filter on attributes like
Category, Country, Region, and Channel name — which live on separate
dimension tables in a normalized model. Two designs were possible:

1. Add `INDEX/MATCH` lookup formulas for those attributes directly on the
   54,573-row Sales fact table (5 lookups × 54,573 rows ≈ 270,000 extra
   formula cells), or
2. Produce a denormalized **reporting table** once during ETL (a single
   pandas merge, mirroring a Power Query "Merge Queries" step) and have all
   downstream formulas read from that instead.

Option 2 was chosen for performance: it keeps the fact table lean and fast,
and avoids hundreds of thousands of repeated per-row lookup formulas for
values that don't change once joined. This is a standard real-world pattern
(star-schema fact table + a flattened reporting/semantic layer) and is
documented here and in cell comments on the Sales_Reporting/Inventory_Reporting
sheets so it isn't mistaken for a shortcut.
